# Review of the supplied master prompt

Reviewed 15 November 2026. The original is preserved in `ORIGINAL_MASTER_PROMPT.md`; the Downloads file is unchanged.

The specification is a strong product brief: organization evidence, immutable versions, independent human approval, tenant isolation, truthful integration states and privacy gates are the right foundations. It is not an implementation or proof of launch readiness.

Problems to fix before using it as a build contract:

1. Twenty stages combine a launch product, advanced administration, external connectors, legal operations and a presentation demo. They need separate acceptance gates. A landing page cannot compensate for an unverified core journey.
2. “Every relevant file,” “all technical stuff,” and worldwide readiness are unbounded. Define supported inputs, roles, browsers, languages, hosting regions, volume, recovery objectives and measured evidence. Do not promise worldwide legal compliance or availability from a build alone.
3. The proposed table and endpoint catalog risks replacing compatible working code. Keep existing names and `/api` contracts; introduce version changes with a compatibility plan.
4. The blanket ban on SECURITY DEFINER conflicts with the existing private, authorized transactional RPC design. Do not silently rewrite access control. Review each existing function for identity, membership, scope, grants and fixed search path; avoid new privileged shortcuts. Document this architectural exception and test it.
5. Missing AI credentials must not prevent local deterministic checks or independent manual review. Label review coverage, never imply a semantic model ran.
6. Privacy must include approved source material sent alongside the draft. A public advertisement can still disclose confidential brand evidence. Recheck policy in the worker immediately before each external attempt.
7. Analysis needs persistent job IDs, bounded leases and recovery. Do not retry non-idempotent external calls under an “exactly once” claim. Record attempts and possible duplicate processing after a worker crash.
8. An operational privacy center must distinguish requests from executed deletion and configured retention from a running purge process. Legal notices remain unpublished drafts until reviewed.
9. Production requires independent SMTP, DNS/TLS, backups/restoration, load/security/accessibility checks, migrations and incident ownership. These are launch blockers, not decorative checklist ticks.
10. The original asks to wait for deployment authorization. The current request authorizes building a deployable app and restoring the existing Supabase project; publishing a public service and buying services remain separate actions.

See `REVISED_MASTER_PROMPT.md` for the revised execution contract and the root tracking files for observed results.
