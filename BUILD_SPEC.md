## Product and outcome
Build an **AI Brand Governance Platform** for growing organizations, marketing teams, agencies, and content creators. Admins maintain approved brand guidelines, terminology, logos, and versioned product facts. Creators submit marketing text, PNG/JPEG images, DOCX, and text-based PDF files for pre-publication checks. The system checks tone, terminology, promotional claims, messaging, basic visual standards, and supported accessibility rules; cites relevant approved sources; explains issues; suggests minimal corrections; and routes a specific content version to an authorized human reviewer. It also shows analytics and the **Living Evidence Graph**: links between claims and approved facts, so changed facts trigger impact previews, affected-content flags, notifications, and human re-review. No auto-publishing or auto-approval.

## Stack and engineering rules
- Frontend: React + TypeScript + Vite + Tailwind CSS + React Router; Recharts for real analytics. Simple, elegant, accessible **white desktop-first UI with a left sidebar**, responsive for mobile; no decorative icons.
- Backend: Python + FastAPI + Pydantic; clean routers, services, repositories, schemas, error handling, OpenAPI docs.
- Supabase: Auth, PostgreSQL, private Storage; SQL migrations in version control; org-scoped Row Level Security, including Storage policies. Use proper foreign keys, indexes, transactions, constraints, and timestamps.
- AI: one configurable backend-only Gemini or OpenAI provider adapter; grounding against approved organization sources; deterministic checks for exact rules; structured, schema-validated model output; no invented evidence/citations. PyMuPDF, python-docx, Pillow/OpenCV for supported file and visual checks.
- Testing: pytest, Vitest, Playwright; real integration and UI tests where dependencies are configured. Pin compatible dependency versions and commit lockfiles. Check current provider docs and installed CLI help instead of guessing commands.
- Security: never expose secrets or Supabase privileged keys in browser; verify tokens and membership/roles on **every** sensitive API operation. Don't authorize from editable user metadata. Enforce RLS, private storage and tenant isolation; validate file type, size, permissions and paths. Treat uploaded documents as untrusted input, not system instructions; minimize sending confidential data to AI and disclose the external provider. Record audit events; handle provider outages honestly.
- Quality: no dummy APIs, fake metrics, inert controls, simulated successful AI checks, or unverified completion claims. Clearly labeled development fixtures for tests are fine; never present them as production data. Handle errors, loading/empty states, accessibility, and failed dependencies. Do not silently modify approved records or publish. Do not deploy or run destructive production operations without my authorization.

**2. Organization + roles:** Workspace creation/onboarding, authorized member invitations, membership and role assignment, organization switcher. Roles: Admin (rules/team), Creator (drafts/corrections), Manager (approval), Reviewer (assigned specialist review). Prevent users from granting themselves higher roles. Test cross-org isolation.

**3. Main app:** Left-sidebar navigation for Dashboard, Brand Knowledge, Facts, Assets, Content, AI Review, Approvals, Evidence Graph, Analytics, Notifications, Team, Settings, and Audit. Show real org-scoped counts, useful empty states, and working links.

**4. Brand Knowledge:** Admin uploads PDF/DOCX guidelines and approved logos, defines colors/tone/terminology/required disclaimers, and creates approved product facts/claims. Extract text with exact document/page/span provenance where available. Extracted suggestions stay unapproved until an admin accepts them. Version rules and facts with source, valid-from/expiry/retired status. Surface conflicting active rules for admin resolution; only approved effective facts may be used as authoritative evidence.

**5. Content Workspace:** Creators compose text or upload JPEG/PNG, text PDF, DOCX; select channel, preview, save draft, and request checks. Store original binary privately; content and versions are immutable and have hashes; validate file size/type. Unsupported scans/video receive a clear limitation message. Never overwrite approved versions.

**6. AI Verification:** Extract content, retrieve only relevant approved org evidence (simple PostgreSQL retrieval first; pgvector optional if useful), run exact terminology/fact checks plus AI tone/claim analysis, validate structured output and every source reference against stored documents. Return category, severity, location/text, explanation, cited fact/rule and version, evidence status `SUPPORTED | CONTRADICTED | INSUFFICIENT_EVIDENCE | NOT_APPLICABLE`, and a minimal correction. Missing evidence is **not** proof of falsehood. Persist analysis and issue records. Provider missing/down => honest blocked/error state, not fabricated results.

**7. Corrections + revisions:** Creator sees before/after, citation and reason; accepts, edits or dismisses each suggestion; can re-run analysis. Persist decision, creator intent and immutable new version. Changes invalidate prior version approvals rather than editing them in place.

**8. Human approval:** Draft -> Analyzed -> Submitted -> Approved / Changes Requested / Rejected. Review queue, comments, assignment, review history and authorized decision actions. Generate an approval/passport record tied to **content-version ID + SHA-256 hash + approver + source/rule versions + timestamp**. Changed content needs new approval. AI cannot make final approval decisions. Approval means “ready to publish,” not connected auto-publishing.

**9. Living Evidence Graph (core innovation):** Store explicit content-claim -> approved-fact-version dependency edges during grounded analysis. Show graph as a simple readable node/edge view or table. When admin proposes/activates a new version of an approved fact, display an impact preview listing affected content, cited old/new facts, current status and required action; on activation, create idempotent impact events, flag affected previously approved content for re-review, notify responsible users, and preserve all historical evidence/approvals. Never flag unrelated content or cross-org content. A fact change must not silently rewrite the existing content. Support a concrete price-change demo (₹1,999 to ₹2,499).

**10. Insights:** Real analytics and persisted notifications: total submissions, issue categories, pending/approved/rejected, review turnaround, repeat violations, affected content and unread alerts. Calculate only from real records; include empty-state visuals and navigation to underlying records.

**11. Visual/Accessibility:** Basic working checks for allowed image dimensions, color palette tolerance, approved asset comparisons only if reliable, contrast where measurable, and required disclaimers. Show “manual review” when uncertain; do not claim full visual or legal compliance. Polish layout, responsive views, keyboard use and validation.
